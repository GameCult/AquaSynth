# Effects shelf

What AquaSynth can render to a WAV today without a window, an audio device or a server: the thruster, the Dings event sounds, the
earcon workshop's families and the playground's synth patches. `shelf.json` is the machine-readable list (generated); the tables
below are generated from it. Both come from `node tools/aqua-feel/shelf.mjs build`.

**Nothing on this shelf has been heard.** Every `listening` field is `unheard`. `node tools/aqua-feel/shelf.mjs check` runs each
entry's render command and proves the file is finite, not silent (peak above -70 dBFS) and as long as listed. It cannot say
that anything sounds good, fits an overlay, or is distinguishable on a stream. A person edits `listening` after listening.

## For overlay packaging

- **No entry reacts to audio.** Nothing here analyses a signal. Entries react to *events* (Ding event ids, earcon event ids), to a
  *control value* (the thruster's `rpm`), or to being *started* (patches). Mapping a StreamPixels event onto any of these is not
  done anywhere in the repo; that mapping is the packager's.
- Two event vocabularies exist and do not match: Dings use task-state ids (`task.complete`, `input.required`, ...), the earcon
  workshop uses `success, fail, warning, message, done, waiting`. The earcon workshop is a separate JS implementation and
  does not sound like the Dings.
- Every command runs from the repo root, needs node >= 20, and writes under `tools/aqua-feel/out/shelf/` (gitignored). Patch and
  Ding renders need the faustwasm runtime once: `(cd tools/aqua-playground && npm ci)`. Earcon renders need nothing installed.
- Patch and Ding WAVs are mono float32 at 48 kHz; earcon WAVs are mono 16-bit at 48 kHz.
- `duration_s` for patches is the 3 s render window, not the effect's length: `behaviour` says whether the patch was still sounding
  at 3 s (sustained) or had died away. Re-render with `--seconds N` for longer.
- Ding loudness uses command gain 0.6, an assumption carried over from `tools/aqua-feel`.

## Render one

```sh
node tools/aqua-feel/shelf.mjs render patch/thruster rpm=2400 --out /tmp/thruster.wav --seconds 5
node tools/aqua-feel/shelf.mjs render ding/task.complete instrument=glass-chime --out /tmp/done.wav
node tools/earcon-workshop/cli.mjs warm-bell /tmp/earcons tempo=1.2 level=0.6     # six WAVs + pack.json
node tools/aqua-feel/shelf.mjs check            # every entry (about two minutes); --only SUBSTR for a subset
```

Each entry in `shelf.json` carries its own `render.command` (the exact string `check` runs) and the files it writes.
Sustained patches such as the thruster keep sounding until stopped; the render command cuts them at the window.

## Not on the shelf

- `tools/aqua-trial`'s `thruster-trial.dsp` (the thruster plus a `noise` percent control): a listening-trial fixture, not an effect.
- `advanced/additive-pad` and `advanced/electro-drop-demo`: they lower to about 1.5 MB of Faust each and are not in the playground.
- The Dings daemon's native libfaust path (`-vec`): the shelf renders through faustwasm, the same host as `tools/aqua-feel`; the two
  have not been diffed.
- Nothing is mapped to StreamPixels events, and no overlay-side player exists in this repo.
